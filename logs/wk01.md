# Week 1

## What I worked on

This week I started learning the basic workflow for building and publishing websites with GitHub.

I worked with repositories and learned how an `index.html` file can become a public webpage through GitHub Pages.

I also started understanding the role of GitHub in a web development project. The repository stores the project files and their history, while GitHub Pages can publish those files as a website.

## What gave me trouble

One thing that initially took some time to understand was the difference between saving, committing, and pushing changes.

At first these actions seemed similar, but I learned that they serve different purposes.

A useful way for me to remember the workflow is:

1. Edit the file.
2. Save the file.
3. Commit the change.
4. Push the commit to GitHub.
5. Check the result.

I also learned that file placement matters. A file existing somewhere in a repository does not necessarily mean the browser will find it where I expect.

## Something new I learned

I learned why `index.html` is important.

When a browser visits the root of a website, `index.html` is commonly used as the default page.

I also learned the difference between something running locally and something published publicly.

A page available at `localhost` or `127.0.0.1` is running on my own computer. GitHub Pages gives the project a public address that another person can visit.

## Working with AI

I noticed that AI can make the process of creating code much faster, but speed can also hide gaps in my understanding.

If AI generates a complete webpage, it may work before I understand why it works.

I found that asking focused questions about individual elements is more useful for learning than simply asking AI to create the whole project for me.

## What I want to improve

I want to become more comfortable looking at an HTML file and understanding its structure without immediately asking AI to explain everything.
