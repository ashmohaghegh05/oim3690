# Week 9 Notes

## What I Worked On

This week I started learning how websites can get data from APIs instead of only using information already stored in the page or entered by the user.

We first talked about what an API is and why it is useful. I learned that an API gives a program a structured way to request data from another service. Instead of manually searching for information, JavaScript can send a request to an API and receive data back.

We also looked at JSON and how API responses are usually structured using objects, arrays, keys, and values. This connected with the JavaScript topics we already learned because understanding objects and arrays makes it easier to understand the data returned by an API.

In class, I practiced using `fetch()` to request data and `await` to wait for the response. I also learned that the response has to be converted using `.json()` before JavaScript can easily work with the returned data.

We also worked with `try/catch` and `response.ok` so the page can handle API errors instead of breaking when a request fails.

Another exercise was the Message Board, where we used a `POST` request to send data to an API instead of only receiving data from it. I also created a Fetch Something Fun exercise where a button requests data from an API and displays part of the response on the page.

## What I Got Stuck On

The biggest thing I found confusing was the difference between `fetch()`, `await`, and `.json()`.

At first, it was difficult to understand why getting data from an API takes several steps instead of immediately giving me the final value.

I also had to think carefully about the structure of the JSON response. Even after the API returns data successfully, I still need to know exactly where the field I want is located inside the object or array.

For example, if the response contains an object inside another object, I need to follow the correct path to reach the value. If I guess the field name incorrectly, the page may show `undefined`.

Another thing I am still getting used to is error handling. I understand that `try/catch` protects the page when something goes wrong, but I need more practice knowing exactly what should go inside the `try` block and what should happen inside `catch`.

## Something New I Learned

I learned that APIs allow websites to use data that they do not own.

This is different from Mini Project 2, where most of the data came from the user and was stored in JavaScript or `localStorage`.

With an API, JavaScript can request outside information such as:

- Weather
- Books
- Recipes
- Town information
- Product information
- Other live or stored data

I also learned the basic API pattern:

1. Send a request using `fetch()`.
2. Wait for the response using `await`.
3. Check whether the response was successful.
4. Convert the response using `.json()`.
5. Read the specific data needed.
6. Show the result on the webpage.

I learned that `async` is usually added to a function when the function contains `await`.

I also learned that a request can use different methods. A normal request can get data, while a `POST` request can send data to a server.

The Message Board exercise helped me understand that APIs can work in both directions. A website can receive information from a server, but it can also send new information to the server.

## AI Observation

This week I noticed that AI can write API code quickly, but it can also guess the structure of an API response incorrectly if it has not actually seen the real data.

Because of that, I learned that I should open the API endpoint myself and inspect the JSON before trusting AI-generated code.

I also found that it is useful to `console.log()` the API response first before trying to display anything on the page. This makes it easier to see the real structure and find the exact fields I need.

For API work, I think AI is most useful when I give it the real API response or documentation instead of only giving it the API name and asking it to guess.

I also noticed that AI sometimes writes more complicated asynchronous code than I need. For this class, I want to keep the code simple enough that I can explain what `fetch()`, `await`, `.json()`, `try/catch`, and `response.ok` are doing.
