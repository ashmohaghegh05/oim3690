## What I Got Stuck On

The biggest thing I had to understand was why putting an API key in `.gitignore` is not enough for a deployed webpage.

At first, it seemed like hiding the key from GitHub should solve the problem.

I learned that if browser-side JavaScript needs the key, the user can still inspect the request or code and potentially see it.

This is why the secret request has to happen on the server side instead.

I also had to understand the difference between:

- the JavaScript that runs in the browser
- the JavaScript inside `api/ask.js` that runs on Vercel

Another confusing part was understanding how the webpage can call `/api/ask` even though the real OpenRouter key is never sent to the browser.

## Something New I Learned

I learned to treat a secret API key like a password.

It should not be:

- hard-coded in JavaScript
- committed to GitHub
- exposed in the browser
- included in a public URL

Instead, the key can be saved as a Vercel environment variable.

For the Ask AI exercise, the environment variable is:

`OPENROUTER_API_KEY`

Then `api/ask.js` can read the key from the server environment while keeping it hidden from the user.

I also learned that a Vercel `api` folder can contain serverless JavaScript functions.

This means a normal webpage can send a request to my own function, and that function can safely make another request to an API that requires a secret key.

A simplified version of the process is:

1. User types a question.
2. `ai-chat.html` sends the question to `/api/ask`.
3. `api/ask.js` receives the question.
4. `api/ask.js` reads the private API key from Vercel.
5. The function sends the question to the model.
6. The model returns an answer.
7. The function sends the answer back to the webpage.
8. JavaScript displays the answer.

## AI Observation

This week made me think differently about AI-generated code.

AI can easily generate code that technically works but handles secrets in an unsafe way.

For example, an AI agent could place an API key directly inside JavaScript because that is the easiest way to make the request work.

The code may work, but that does not mean it is safe.

I need to understand where code runs and whether information is visible to the browser before accepting an AI-generated solution.

I also learned that I should read the actual API response and code instead of assuming the AI guessed the correct fields or request structure.
